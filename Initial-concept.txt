What already exists nearby: Have you looked at EngineeringPaper.xyz? It's close to what you're describing — Mathcad-style visible calculations, native units (via Pint under the hood), web-based. Not spreadsheet-shaped though. Also handcalcs is a Jupyter extension that renders Python math in Mathcad-style notation.
The hard part is the reactive execution model. Spreadsheets are a dataflow graph — change a cell, dependents update automatically. Python is imperative/sequential. You'd basically need to build a dependency tracker that re-executes downstream cells when inputs change. Observable notebooks and Marimo (a reactive Python notebook) have solved this, but bolting spreadsheet UI on top of it is a different beast.
"Easy as Excel" is the real killer. Excel's genius is direct manipulation — click a cell, type, see result. The moment you ask users to think about variable scoping, object names, or Python syntax, you've lost most of the Excel audience. The people who'd actually use your tool are engineers who already know Python — and they might just use Jupyter + Pint + handcalcs.
Units are solvable — Pint is mature and handles dimensional analysis well. The UX of units in a spreadsheet context is the tricky part (how do you display them, convert them, handle mismatches gracefully).
The "mini spreadsheets as named objects" idea is the most novel part. That's essentially structured data blocks with reactive evaluation — kind of like named ranges in Excel but with Python semantics. You could go even simpler and just re-run top to bottom every time.
The main issues with brute-force re-execution:

Side effects: if a cell writes a file, hits an API, or prints something, it fires every time. Probably not a big deal for your use case.
Slow cells: if someone has a big FEA mesh or Monte Carlo in one cell, re-running it because they changed an unrelated label is annoying. But you could handle this with a "freeze" toggle on expensive cells.
Execution order: top-to-bottom is simple and predictable. Reactive/dependency-based execution lets cells be in any visual order, which is powerful but confusing. Top-to-bottom is more spreadsheet-like honestly — people expect left-to-right, top-to-bottom.

I'd say start with full re-execution top-to-bottom. It's dead simple, easy to reason about, and you can always add dependency tracking later as an optimization.
